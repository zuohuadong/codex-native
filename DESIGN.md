# Desktop visual contract

ZCode 3.16.2, commit `3c5b227649371507ddc4eb46ac5133afe6db1cab`, is the visual authority. Implement its layout and styling in pure Rust/GPUI; WebView and hybrid rendering are excluded by user instruction. Light is the default; saved light/dark/system choices remain supported. Codex 21477 and 8109 captures are historical diagnostics, not ZCode acceptance evidence. Full visual parity remains unverified.

- Default content size: 1200 × 800. Minimum supported window: 480 × 640. Historical 1180 × 760 and 480 × 600 captures remain diagnostic reference targets; the native window bounds follow the current ZCode desktop contract.
- Chat sidebar: 268px, hidden below 820px. Settings sidebar: 268px, compact 68px below 1024px; compact targets 40px. Compact header keeps navigation accessible.
- Chat sidebar structure follows the ZCode shell: a 48px top clearance with 96px left clearance for traffic lights followed directly by sidebar collapse (`Glyph::PanelLeftClose`), back (`Glyph::ArrowLeft`), and forward (`Glyph::ArrowRight`) buttons without a brand title. Primary navigation uses 4px block / 8px inline padding and 4px gaps (`新建任务` with `⌘N` shortcut badge, `自动化` with `Glyph::CalendarClock`, `插件市场` with `Glyph::Package`), 32px navigation rows with 8px radius. The task list section is introduced with a `任务列表` header row hosting Search (`Glyph::Search`) and Filter (`Glyph::FileText`) icon buttons. The search input expands on demand or filter. Subsections `项目` (with active workspace pill) and `任务` (with task list) follow. Idle task rows omit leading chat bubbles. The footer is split: User avatar circle with `连接使用` on the left, and Settings (`Glyph::Settings`) gear button on the right.
- Header: 48px (`h-12`). Actions: 28px target, 16px vector icon. Draft mode header has transparent border; active conversation header has subtle `border-b border-border/50` border. Title section displays workspace folder button (`Glyph::Folder`, tooltip with directory) and 14px semibold title. Header right controls place terminal toggle (`Glyph::Terminal`) and review side pane toggle (`Glyph::PanelRightClose` / `Glyph::PanelRightOpen` on the far right edge). The compact header keeps New task, History, Skills, Automations, Settings, Review, and Command entries reachable at the supported 480px minimum.
- Message row actions follow `ConversationRowView.tsx`: User message row provides Copy (`Glyph::Copy`) and Edit (`Glyph::Pencil`, populates textarea and focuses composer); Assistant message row provides Copy, Thumbs up reaction (`Glyph::ThumbsUp`, active green), Thumbs down reaction (`Glyph::ThumbsDown`, active amber), and derived 12px time label in `foreground_subtlest`.
- Review is an optional 380px side pane at widths >=1180px and replaces the conversation as a single content pane below 1180px; closing it restores the conversation. The pane header is 48px with 14px semibold title, 28px ghost refresh (`Glyph::RefreshCw`), and 28px ghost close (`Glyph::X`). File list, diff container, and status surfaces use semantic `card_border` (`rgba(13, 13, 13, 0.1)` light / `rgba(255, 255, 255, 0.1)` dark). Mode tabs (Unstaged, Staged, Untracked) and search remain fixed above independently scrolling file and diff sections. Loading, error, empty-category and no-match states remain distinct.
- Command output is an optional bottom drawer bound to the active conversation; it is a command runner, not a PTY terminal emulator. Its height is 30% of the viewport capped at 210px, with a fixed header/close action, selectable 14px/20px monospace output, per-result error treatment, explicit empty/running states and a fixed run row. Output consumes wheel input only while it can scroll in that direction.
- Streaming text respects reduced motion and is enabled only for the current last assistant row; completed history stays static. New assistant text fades in over 900ms with cubic-bezier(0.16, 1, 0.3, 1). The stylesheet does not assign a per-token delay, so one update fades together. Empty assistant rows remain unrendered rather than showing placeholder prose, and stopped runs use a neutral notice distinct from the red provider/tool failure notice. Buttons and fields use the component library's focus/keyboard behavior and explicit labels.
- Running work, queue pause, provider failure, unavailable preview, missing credentials, and persistence failure must remain distinguishable. A local state change cannot stand in for a completed external operation.

The active contract and dynamic capture procedure live in `docs/visual-parity/`. A screenshot capture does not prove the action or backend postcondition. See `docs/desktop-restoration-status.md` for implementation and acceptance evidence.
