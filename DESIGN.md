# Desktop visual contract

ZCode 3.16.2, commit `3c5b227649371507ddc4eb46ac5133afe6db1cab`, is the visual authority. Implement its layout and styling in pure Rust/GPUI; WebView and hybrid rendering are excluded by user instruction. Light is the default; saved light/dark/system choices remain supported. Codex 21477 and 8109 captures are historical diagnostics, not ZCode acceptance evidence. Full visual parity remains unverified.

- Default content size: 1180 × 760. Minimum supported window: 480 × 480.
- Chat sidebar: 268px, hidden below 820px. Settings sidebar: 268px, compact 68px below 1024px; compact targets 40px. Compact header keeps navigation accessible.
- Chat sidebar structure follows the ZCode shell: a 48px top clearance, primary navigation with 12px block / 8px inline padding and 4px gaps, 32px navigation rows with 6px radius, a bordered list region with 12px top padding and the only vertical scroll, 31px history rows, and a fixed Settings footer separated by a border. Skills precedes Automations; no remote, upgrade, account, or avatar surface is added. The list title, workspace row, search, and History label share the list region; their text truncates within 268px.
- Header: 40px. Actions: 28px target, 16px vector icon. The compact header keeps New task, History, Skills, Automations, Settings, Review, and Command entries reachable at the supported 480px minimum; the title owns the remaining flexible width and truncates. Hover uses the 5% Zai hover surface, while selected ghost controls use the stronger selected surface.
- Body: 14px, metadata: 12px, ordinary headings: 18px; settings titles: 30px wide / 24px compact. Use platform system sans and monospaced code rendering.
- Navigation radius: 6px; controls: 8px; cards: 12px; composer: 16px; user messages: 12px with a 2px top-right corner.
- Colors are owned by `crates/pi-desktop/src/theme.rs`. Components follow the selected system/light/dark mode.
- Review is an optional 380px side pane at widths >=1180px and replaces the conversation as a single content pane below 1180px; closing it restores the conversation. The header keeps refresh/close actions, the mode tabs and search fixed above independently scrolling file and diff sections. Loading, error, empty-category and no-match states remain distinct.
- Command output is an optional bottom drawer bound to the active conversation; it is a command runner, not a PTY terminal emulator. Its height is 30% of the viewport capped at 210px, with a fixed header/close action, selectable 14px/20px monospace output, per-result error treatment, explicit empty/running states and a fixed run row. Output consumes wheel input only while it can scroll in that direction.
- Streaming text respects reduced motion and is enabled only for the current last assistant row; completed history stays static. Empty assistant rows remain unrendered rather than showing placeholder prose, and stopped runs use a neutral notice distinct from the red provider/tool failure notice. Buttons and fields use the component library's focus/keyboard behavior and explicit labels.
- Running work, queue pause, provider failure, unavailable preview, missing credentials, and persistence failure must remain distinguishable. A local state change cannot stand in for a completed external operation.

The active contract and dynamic capture procedure live in `docs/visual-parity/`. A screenshot capture does not prove the action or backend postcondition. See `docs/desktop-restoration-status.md` for implementation and acceptance evidence.

Settings rows use 16px horizontal / 12px vertical padding, 16px column gap, medium labels, 24px description line height and alpha borders. Default rows retain a 192px right control column at compact widths, matching the reference grid. Language/theme use native dropdowns; their actual popup/focus appearance still requires comparison.

Draft conversation layout follows the reference timeline: leading spacer has a 29% viewport-height basis and 52px minimum; trailing spacer grows with a 16px minimum. Greeting uses a 30px maximum, 20px minimum, and measures its rendered text against the available content width; line height is 1.2, with 32px bottom separation at widths >=640px and 40px below. Native rendering still needs screenshot validation; background artwork and rendered font-fit acceptance remain pending.

User bubble source: ZCode `packages/ui/src/v4/ConversationUserInputBubble.tsx`. Use a 1px alpha border, 16px horizontal / 12px vertical padding and neutral alpha surface (light black 3%, dark white 5%). At conversation widths >=624px the maximum bubble width is 576px; narrower conversations use the available transcript width. These parameters are source-aligned; native screenshot acceptance remains pending.

Conversation messages use the ZCode V4 user-input bubble contract: neutral surface, 1px border, 12px radius with a 2px top-right radius, 14px text and 24px line height. Pure helpers now pin the 624px/576px/32px bubble-width rule and the 120px-plus-1px collapse threshold, in addition to the previously implemented measured wrapped text, fade and disclosure key. Workflow cards open a native detail dialog from the expand control; option controls remain disabled. The dialog retains the same stage and disclosure rendering, observes the source chat, and limits its dimensions to the current window.

User input content is rendered as native plain text so Markdown markers remain literal, matching `ConversationUserInputContent`; assistant content continues through Markdown rendering; raw tool output uses selectable monospaced plain text.

Raw tool results use native selectable text, avoiding Markdown fence interpretation. Bash/execute/shell output follows `ToolCallBlocks/renderers/ExecuteOutput.tsx`: 14px monospace, 20px line height, 100px maximum scrolling content height. Other raw output uses 12px text with a 200px scroll limit inspired by the fallback renderer. The inner output view consumes wheel input only while it can still scroll in that direction; at either edge the event continues to the transcript, matching nested overflow behavior while keeping an in-result scroll from changing FOLLOWING/DETACHED intent. Unit tests cover the edge rule; rendered follow/freeze, selection and wheel replay remain pending.

Workflow agent pills follow `WorkflowAgentPill.tsx`: 32px height, 8px left / 10px right padding, 8px content gap, and a 14px trailing status mark. Agent faces have a 20px minimum size from `.wf-face` in `styles.css`, overriding the component's `size-4`; script glyphs remain 16px. Faces use the reference 20-unit coordinates and 7px body radius. Static eye expressions carry status even with reduced motion; their exact native rendering still requires matched screenshot acceptance.

Stage lamps are centered 17px from the column's left edge; headings start at 34px and use 13px medium text. Stage fractions use 12px monospaced text, separated by 8px. Fractions come from explicit executor-observed settled/observed counters; absent, empty or invalid counts are omitted rather than inferred from planned rows.

Long user messages use the source-aligned 120px collapsed content limit. Native GPUI measures wrapped text with the active font and bubble width, keeps selectable text, and provides an in-bubble expand/collapse control only when the measured height overflows. Disclosure keys include session, message ID and content so edits reset the collapsed state.

Collapsed message fade: bottom 36px (70–100% of 120px), transparent-to-composited bubble surface, vertical direction. The native overlay approximates the reference alpha mask on the current flat chat background; selection compositing and screenshot acceptance remain pending. Expand/collapse button is 32×24px with a 16px chevron and small shadow.

Theme authority is the `.theme-zai-light` / `.theme-zai-dark` cascade in the pinned ZCode `styles.css`, not its earlier generic `@theme` / `.dark` declarations. Preserve root backgrounds #f8f8f8 / #161616 and sidebar backgrounds #f0f0f0 / #161616. Secondary foreground is RGBA #262626 at 60% (light) / #d4d4d4 at 60% (dark); tertiary foreground uses 40% / 30%. These must be alpha-composited over each actual surface, not replaced with fixed terminal-palette gray.

Settings shell: reference `SettingsPage.tsx` uses a 4px top/right/bottom panel inset on macOS without an extra left inset; compact macOS top clearance is 64px. Frame border uses the alpha border token. Content columns have a 32px vertical gap and 32px bottom padding compact / 40px wide. Titles use 24px/32px compact and 30px/36px wide. These source-based corrections still need fresh screenshot acceptance.

Native component theme projection: custom surfaces and gpui-kit controls share the Zai foreground, border, popup, list, primary-button and neutral focus-border palette, with a 14px base font. Apply updates via `Theme::update` to reconcile styled tokens and Base projection; compare first to avoid refreshing unchanged frames. Input/Select backgrounds are explicitly white in light and #2b2b2b in dark because the library otherwise derives a translucent dark input fill from its border token. Remaining component-specific hover/disabled/switch-thumb details require reference capture verification.

The settings switch uses the native Base Switch semantics with application-owned 32x18 geometry, 16px thumb, 1px inset and 14px travel. Track and thumb position transition over 150ms with cubic-bezier(0.4, 0, 0.2, 1), matching the reference Tailwind defaults; reduced motion settles immediately. The transparent pointer extension is 12px horizontally and 8px vertically without changing row layout. Preserve a native focus indicator and switch accessibility role. Rendered geometry, the extended pointer target and keyboard acceptance remain pending an unlocked capture.

Workflow adjacent-stage headings use the 192px station pitch and a flexible rail after title/counter (minimum 12px, 10px leading gap, -6px trailing margin). Running faces use separate open/closed eye paths with 230ms double blinks and 360ms gaze travel to -4px; waiting dots rise 1.5px over 500ms with 200ms stagger. Completed faces use a bounded 8530ms hop and blink cycle; failed faces use a bounded 8000ms float and shake cycle. These are deterministic native approximations of the reference scheduler; independent random timing and running-state focused/confused expressions remain pending. Reduced-motion rendering stays static.

Workflow node details and deliverables are selectable native text, capped at 160px with independent vertical scrolling and stable workflow-scoped selection IDs. The 160px cap is a native containment choice, not a measured reference dimension; actual wrapping, selection and wheel behavior remain pending GUI acceptance.

Workflow header capability rule: expose Configure only when a real settings amendment host exists; do not substitute a read-only details dialog. Status, workflow name and metadata have separate emphasis: medium primary status, subtle name with 80px minimum, and 14px tertiary metadata. Native header wrapping still requires matched GUI validation.

Conversation scrolling follows an explicit local FOLLOWING/DETACHED state. Streaming updates keep the transcript pinned only while the user remains at the bottom; any upward wheel gesture detaches immediately, and a 32px circular return control floats above the composer without changing transcript layout. Per-session scroll memory is renderer-local and bounded to 200 sessions; GUI wheel, keyboard, and session-switch acceptance remain pending.

The transcript now owns a native focus target and handles PageUp/PageDown, Home/End, ArrowUp/ArrowDown and Shift+Space. Modifier combinations are left to the focused editor. The state transition is unit tested, but native key focus traversal and scrollbar drag behavior still need an unlocked GUI replay.

Skills follows the ZCode resource pattern more closely: a grouped surface with a count, compact 36px icon tile, one-line name/description hierarchy, hover treatment, keyboard-focusable detail action, and a bounded native detail dialog containing description, instructions and examples. “Use in task” still inserts the real built-in prompt into the composer.

Automations follows the ZCode task-card geometry: 132px cards in two columns at wide widths and one column below 1024px, 226px empty state, compact schedule/status metadata, and a top-right action menu. The existing local interval execution semantics remain unchanged; cloud recurrence and history are outside this native implementation.

Workflow card headers use card-level status wording (`Workflow running`, `Workflow completed`, `Workflow errored`, `Workflow stopped`) while node pills retain their shorter node-level status wording.

Automation editing now uses a native multi-line Instructions field with 5–7 auto-growing rows, a 116–156px height range, 14px/20px typography, and 6px label spacing. Name and interval remain single-line validated fields.

Nested workflow timeline, delivery, and node-detail scroll areas stop propagation before the transcript intent handler. Tool output now stops propagation only while its own scroll range can consume the wheel direction; at its top/bottom edge or when it is not scrollable, the event reaches the transcript. This preserves normal outer scrolling without letting an in-result scroll change the outer chat's FOLLOWING/DETACHED state. Native pointer replay and keyboard/scrollbar intent still require GUI verification.

Screenshot validation remains pending.
