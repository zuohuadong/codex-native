# Conversation workflow card

The user's screenshot is an inline conversation state, not a separate automation page. Keep pure GPUI rendering.

The reference specifically shows agents invoked during a conversation: bind the card to that turn and update it from executor events. Stage columns describe execution order, and multiple pills within a stage describe its agents/scripts. The header summarizes live status and running-agent count; deliverables and attributed file changes belong to that run. Preserve this structure in both themes, with light as the default. A five-stage fixture demonstrates the reference layout only; the current bounded analysis delegation does not establish full five-stage orchestration.

Implemented foundation:

- `WorkflowUpdated(WorkflowSnapshot)` carries explicit workflow identity, monotonic revision, parent user-message ID, model, stages and agent/script nodes.
- Snapshots live in the session's persisted task state. Cards render immediately after the referenced user message, inside the transcript, with a 1104px maximum width.
- 168px stage columns, 24px column gaps, 32px node pills, 12px outer radius, 20px agent badges and 16px script glyphs. Narrow layouts scroll the stage row horizontally.
- Stage headings have short connector lines. The active stage uses an orange dot with a translucent ring; failed nodes use the theme error color. Agent badges use status-specific eye shapes with an optional executor-provided avatar index into the reference nine-color palette; legacy nodes use the reference Unicode name hash, while scripts retain a terminal glyph. Truncated node labels expose full names and status through tooltips. Colors live in the light/dark theme tokens.
- Header collapse, node-detail expansion and deliverable expansion use the existing persisted disclosure state. The expanded header uses a workflow icon with reserved option/expand affordances, node rows have 6px vertical spacing, and the deliverables control is a fixed 112 x 32px filled button. Waiting nodes omit the trailing status glyph while retaining their accessible status label. These refinements are source/reference based and still require rendered screenshot comparison.
- Running-agent count excludes scripts. Late revisions cannot regress a snapshot or move it to a different conversation turn.
- Restart and run termination interrupt unfinished running nodes; completed nodes remain completed.
- Ordinary tool events do not produce workflow cards. Existing history defaults to no workflow.
- Workflow snapshots optionally carry attributed file changes. A separate 40px-minimum summary row below the card displays file count and added/removed lines; expanding it lists paths and per-file counts. Uncounted/binary changes are explicitly labeled. The disabled Undo control has no mutation handler.

`scripts/visual_parity/fixtures/multi-agent.json` is an explicitly labeled completed offline sample with five stages. It is not evidence of agent dispatch or parallel execution.
